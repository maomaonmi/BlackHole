## 1. 问题定义

### 1.1 用户诉求（原话）

> 「当前的恒星拉扯轨迹和恒星本体是分离的，那么真实的恒星会被黑洞在不同方向拉扯，轨迹是随着拉扯力度和时间、距离变化的，不应该是分离的。」

拆解为三条可验收的诉求：

| 编号 | 诉求 | 含义 |
|------|------|------|
| R1 | 消除分离感 | 轨迹起点必须长在本体表面，接缝处无断口、无宽度跳变 |
| R2 | 拉伸随**距离**变化 | 越靠近黑洞，本体被拉得越长越细 |
| R3 | 拉伸随**时间**变化 | 撕裂是一个有进度的过程（渐进剥离），不是瞬间切换 |

### 1.2 现状复现

拖动恒星靠近黑洞时，可以同时看到两个互不相关的形态：

1. 本体被压成一个**椭圆**（形状像被捏扁的球，不朝黑洞方向拉长）；
2. 一条**独立**的能量流从恒星附近某处起飞，飞向黑洞。流的长度只与"恒星活了多久"有关，与恒星离黑洞多近毫无关系——恒星刚生成、离黑洞很远时，流照样是满长的。

两者之间有一段明显的**空隙或错位**。

### 2.2 本体只做**均匀仿射**

[star_frag.glsl](file:///d:/BlackHole/kerr/shaders/star_frag.glsl#L684-L692)：

```glsl
float stretchToward = 1.0 + inf * 1.0;   // 常数：与像素在球面上的位置无关
float stretchAway   = 1.0 + inf * 0.2;
float expandPerp    = 1.0 + inf * 0.2;
float parallelScale = dParallel > 0.0 ? stretchToward : stretchAway;
float distFactor    = dParallel > 0.0 ? 1.0 + (dParallel / R) * inf * 0.1 : 1.0;
dParallel /= parallelScale * distFactor;
dPerp     *= expandPerp;
```

`parallelScale` / `expandPerp` 对**所有像素取同一个常数**，因此无论怎么调参，形状恒为**椭圆**，不会出现泪滴；而且 `dParallel`、`dPerp` 各自乘常数、**不平移**，质心不动，所以永远"贴着原来的位置"，不会朝黑洞方向探出长鼻。

## 3. 物理模型（用于定义形变，不追求严格数值拟合）

采用牛顿潮汐近似（观众只需要"看起来对"，不需要广义相对论精度）：

| 量 | 定义 | 用途 |
|----|------|------|
| $r$ | 星心→洞心距离（aspect 校正 UV） | 输入 |
| $r_t$ | 潮汐半径（可调，默认 ≈ 0.30 UV） | 阈值 |
| $\beta = r_t / r$ | 穿透因子 | $\beta > 1$ 才算进入撕裂区 |
| $T(r) = (r_t/r)^3 = \beta^3$ | 潮汐强度（∝ $r^{-3}$，牛顿潮汐加速度差 $\Delta a \simeq 2GM_\bullet R_*/r^3$ 的标度） | 驱动剥离速率 |
| $p \in [0,1]$ | 剥离进度 | 核心状态量 |
| $\Lambda = 1/(1-p)$ | 拉伸倍率 | 形变强度 |

**剥离进度积分模型**（R2 + R3 的数学表达：同时随距离和时间演化）：

$$\dot p = k\,T(r)\,(1-p)\quad (T>1),\qquad \dot p = -\eta\,(1-T)\,p\quad (T\le 1)$$

- 第一式：越近（$T$ 越大）剥离越快，且 `(1-p)` 使过程渐进收敛；
- 第二式：恒星被拖离后缓慢**愈合**，保证现有"拖动恒星跟随鼠标"的玩法不被破坏。

**3D 潮汐张量** $\mathrm{diag}(+1,+1,-2)$：径向拉伸、横向压缩 → 这正是"越拉越细"的来源，也是横向压缩系数取 $\approx 0.55\,\Lambda$ 的依据。

## 4. 设计目标与验收标准

| 编号 | 目标 | 验收方式 |
|------|------|----------|
| G1 | 本体形态随 $\Lambda$ 变为**不对称泪滴**（朝洞侧长鼻、背洞侧保持圆） | 拖近黑洞截图：形状不再是椭圆，长轴指向洞心且前尖后钝 |
| G2 | 流**起点**精确落在本体鼻尖 | 关闭流底噪后，接缝处无空隙、无重叠亮斑 |
| G3 | 流**起点宽度** = 本体鼻部宽度 | 连续拉伸参数时接缝处宽度无跳变 |
| G4 | 流长度/亮度由 $p$ 驱动，不再由 `age` 驱动 | 恒星刚生成且远离黑洞时，流几乎不可见 |
| G5 | 恒星远离黑洞后形态**平滑复原** | 拖出潮汐半径 2~3 秒内回到近球体 |
| G6 | 形体不出现数值爆炸 / 折叠 / 镜像 | $\Lambda$ 拉满时边界仍单调、无自交 |
| G7 | 现有阶段（白矮星/中子星/黑洞桥）行为不回归 | WD/NS/mini-BH 能量桥观感与改前一致 |

### 4.1 非目标（本批次不做）

- 不做真实广义相对论潮汐（自旋、自转、轨道偏心率），仅做视觉正确的牛顿近似。
- 不做流体的 3D 体积渲染，沿用现有 2D 贝塞尔 + 解析螺旋管线。
- 不改变恒星的**生命周期与交互逻辑**（左键生成 / 右键演化 / 中键坍缩全部不动）。

## 5. 方案总览

**核心决策：保留现有双 Shader 架构，通过"共享同一物理状态 + 交界不变量"做连续缝合。**

> 理由：把本体与流合并进单个 shader 需要重写两套独立的时间基、坐标基与球面程序化材质，风险与工作量都远高于"对齐接口"。双 shader 的分离感来自**接口未定义**，而不是架构本身错误。

```
                    ┌──────────────────────────────────────┐
   拖动恒星 ──────► │  S1  统一潮汐物理状态 (CPU)            │
                    │  每帧积分 p / Λ / r，存于 StarObj      │
                    └───────────────┬──────────────────────┘
                                    │ 同一组数值
                    ┌───────────────┴──────────────────────┐
                    ▼                                      ▼
      ┌───────────────────────────┐        ┌───────────────────────────┐
      │ S2  本体泪滴形变            │        │ S3  流从本体真实表面长出    │
      │ star_frag.glsl             │        │ energy_stream_frag.glsl    │
      │ 位置相关非均匀拉伸 + 横向压缩 │        │ 起点/宽度/强度由 p、Λ、R 导出 │
      └───────────────┬───────────┘        └───────────────┬───────────┘
                      └────────────┬───────────────────────┘
                                   ▼
                    ┌──────────────────────────────────────┐
                    │  S4  交界不变量                       │
                    │  noseLen / noseWidth 两处公式完全一致  │
                    └──────────────────────────────────────┘
```

## 6. 详细设计

### 6.1 S1：统一潮汐物理状态（CPU）

**新增 `StarObj` 字段**（[main.cpp](file:///d:/BlackHole/kerr/src/main.cpp#L226-L260) 结构体内追加）：

| 字段 | 类型 | 含义 |
|------|------|------|
| `tidalProgress` | float | $p \in [0, 0.96]$ 剥离进度 |
| `tidalLambda` | float | $\Lambda = 1/(1-p)$ 拉伸倍率，上限 ≈ 25 |
| `tidalDist` | float | 本帧 $r$（UV，aspect 校正） |
| `tidalRt` | float | 本帧生效的潮汐半径（便于调试显示） |

**每帧更新**（放在恒星更新循环内、紧邻现有 `s.age += dt`）：

```cpp
// Why: 本体与流必须由同一物理量驱动，否则两者形态互相独立（历史 bug）
{
    float dx = bhCx - s.x, dy = bhCy - s.y;
    float r  = sqrtf(dx*dx + dy*dy) + 1e-4f;
    float T  = powf(config.tidalRadius / r, 3.0f);      // 潮汐强度 ∝ r^-3

    if (T > 1.0f)
        s.tidalProgress += config.tidalRate * T * (1.0f - s.tidalProgress) * dt;
    else
        s.tidalProgress -= config.tidalHealRate * (1.0f - T) * s.tidalProgress * dt;  // 愈合

    s.tidalProgress = Clampf(s.tidalProgress, 0.0f, 0.96f);   // 0.96 → Λ≤25，防发散
    s.tidalLambda   = (config.tidalEnabled && s.stage == STAGE_NORMAL)
                    ? 1.0f / (1.0f - s.tidalProgress) : 1.0f;
    s.tidalDist     = r;
}
```

**要点**

- `tidalLambda = 1` 是**单位元**：关闭开关或非普通恒星时，全部下游形变为恒等变换，与现状严格一致（可回滚）。
- 只在 `STAGE_NORMAL` 生效，白矮星/中子星/黑洞桥不受影响（G7）。
- `Clampf` 上限 0.96 而非 1.0，避免 $\Lambda \to \infty$ 造成顶点飞散（G6）。

### 6.2 S2：本体泪滴形变（`star_frag.glsl`）

**原理（逆向映射）**：shader 用 `d = vUV - uStarPos` 计算 `nr = |d|/R` 判定球体，因此**把采样坐标 `d` 收缩** = 视觉上把形体**放大/拉长**。收缩得越厉害、且收缩量随位置变化，拉伸就越强——这就是与现状"乘常数"的本质区别。

**替换** [star_frag.glsl L669-696](file:///d:/BlackHole/kerr/shaders/star_frag.glsl#L669-L696) 的潮汐块：

```glsl
// 潮汐泪滴形变：位置相关、非均匀、不对称
// 逆向映射：canonical = Φ(physical)，形体可见域为 |canonical| <= R
if (uTidalLambda > 1.001 && uStarStage == 0) {
    vec2 bd = uBHPos - uStarPos;  bd.x *= aspect;
    float bdLen = length(bd);
    if (bdLen > 0.001) {
        vec2 n = bd / bdLen;                 // 星 → 洞方向
        vec2 q = vec2(-n.y, n.x);

        float xi  = dot(d, n) / R;           // [-1,1] 内，+ = 朝洞侧
        float dPar  = dot(d, n);
        float dPerp = dot(d, q);

        float L = uTidalLambda - 1.0;                              // Λ-1

        // 位置权重：朝洞侧趋近 1，背洞侧趋近 0 → 不对称（只有朝向洞的一侧被拉长）
        float w = pow(clamp(0.5 + 0.5 * xi, 0.0, 1.0), 1.5);

        float A = 1.0 + L * w * uTidalStretch;   // 径向拉伸因子（>1 → canonical 收缩 → 变长）
        float B = 1.0 + (A - 1.0) * 0.55;        // 横向压缩因子（≈保面积 → 越拉越细）

        dPar  /= A;                              // 拉长
        dPerp *= B;                              // 变细（注意：乘 >1 才是压缩）

        d = dPar * n + dPerp * q;
    }
}
```

**为什么这样能出泪滴**

- $A$ 随 $xi$ 单调增：$xi=-1$（背洞）时 $w=0 \Rightarrow A=1$ 不变形，仍是圆的；$xi=+1$（朝洞）时 $A=1+L$，拉得最长 → 前尖后钝。
- $B$ 同样随 $xi$ 增：鼻部同时变细 → 由"长椭圆"变成有尖端的泪滴。
- 鼻尖位置可解析求出：物理 $d_\parallel$ 处的 canonical 为 $d_\parallel/A(d_\parallel/R)$，边界条件 $=R$ 得 $d_\parallel^{tip} = R\,(1 + L\cdot uTidalStretch)$。**这个值就是 S4 的 `noseLen`。**

### 6.4 S4：交界不变量（本方案的正确性核心）

**不变量定义**

| 名称 | 公式 | 出现位置 |
|------|------|----------|
| `noseLen` | $R \cdot (1 + (\Lambda-1)\cdot \text{uTidalStretch})$ | 本体：鼻尖位置推导值；流：`p0` 偏移 |
| `noseWidth` | $2R / (1 + (\Lambda-1)\cdot\text{uTidalStretch}\cdot 0.55)$ | 本体：鼻部半宽 $\times 2$；流：`wBase(s=0)` |

**必须满足**

1. 同一 `uTidalStretch`、同一 aspect 校正空间（**都乘 aspect、都不乘**——本体内 `bd.x *= aspect`，流内 `star_corr.x * aspect`，两者已在同一空间，公式可直接共用）；
2. 形参 `uTidalStretch` 只允许有一个来源（`config.tidalStretch`），禁止在某一侧硬编码；
3. 当 `Λ = 1` 时，`noseLen = R`、`noseWidth = 2R`，两式自动退化为恒等 → 与现状一致（回滚安全）；
4. `p0` 处流宽必须等于 `noseWidth`，且亮度的 `s→0` 极限应与本体边缘亮度同量级（避免"亮头接暗尾"）。

**验证方法**：把 `tidalStretch` 与 `tidalRate` 拉到极端（Λ→25），缓慢来回拖动恒星，在接缝处观察：不应出现空隙、重叠亮斑、宽度台阶。

## 9. 风险与缓解

| 编号 | 风险 | 等级 | 缓解 |
|------|------|------|------|
| RK1 | $\Lambda$ 在 $p \to 1$ 时发散，顶点飞散 | 高 | `p` 硬上限 0.96（$\Lambda \le 25$）；`A`、`B` 再做 `max(..., 0.08)` 保护 |
| RK2 | 位置相关映射**非单调** → 形状折叠/镜像 | 高 | Step 2 前先用 §10 的独立数值测试验证 $\Phi$ 严格单调；`uTidalStretch` 上限 4 并配测试 |
| RK3 | aspect 校正不一致导致接缝错位 | 中 | S4 明确"双端同空间"；接缝测试纳入验收 |
| RK4 | `p` 在潮汐边界反复进出 → 形态抖动 | 中 | 愈合项 `(1-T)` 在 $T\to1$ 时自动趋零，天然平滑；必要时加滞回 |
| RK5 | 本体边缘 `discard` 在拉伸后出现硬边锯齿 | 低 | `smoothstep` 软化边缘（Step 2 一并做） |
| RK6 | 流起点用真实 `uStarSize` 后，极小恒星（`uStarSize` 很小）流变得过细看不见 | 低 | `noseWidth` 设下限（如 0.006 UV） |
| RK7 | 白矮星/中子星/黑洞桥被动到 | 中 | 所有形变以 `s.stage == STAGE_NORMAL` 为前置条件；能量桥的 `baseIntensity` 单列分支 |
| RK8 | 坐标/单位误用（`config.holeRadius` 的 UV 语义） | 中 | 实施前先核对 `holeRadius` 单位并加注释；见 §12 待确认项 |

### 10.3 单元测试思路（针对复杂数学：$\Phi$ 映射）

> 形变公式是本方案唯一有数学风险的部分。GLSL 无法单元测试，因此把它**镜像成纯 C++ 函数**（同一份公式，禁止另写一套），用一个独立的小测试 `tidal_map_test` 断言：

```cpp
// 被测：canonical = xi / A(xi)，A(xi) = 1 + L*w(xi)*stretch
// 测试 1：单调性 —— 在 xi ∈ [-1.5, 1.5] 上以 1e-3 步长采样，
//         断言 canonical 严格单调递增（无折叠/镜像）→ 覆盖 RK2
// 测试 2：恒等退化 —— L = 0（Lambda=1）时，canonical == xi（逐点 1e-6）→ 覆盖 RK7 / 回滚安全
// 测试 3：鼻尖解析解 —— 二分求解 canonical(xi*) == R，
//         断言 xi* ≈ 1 + L*stretch（相对误差 < 1e-3）→ 覆盖 S4 的 noseLen 公式
// 测试 4：有界性 —— p = 0.96（Lambda = 25）时，A/B 有限且 > 0 → 覆盖 RK1
// 测试 5：横向宽度 —— 在 xi = 1 + L*stretch 处，半宽 == 0（尖端收敛）；
//         在 xi = -1 处，半宽 == R（背侧保持圆）→ 覆盖 G1 形状断言
```

**测试与 Shader 一致性保障**：C++ 镜像函数与 GLSL 必须由同一段注释锚定（写明"与 `star_frag.glsl` §Tidal 保持一致，改一处必须改两处"）。

### 10.4 接缝数值自检

在 CPU 侧打印（调参模式）`noseLen` 与 `noseWidth`，并与流 shader 内同式计算结果比对，断言 `fabs(diff) < 1e-6`。这能在"改了一边忘了另一边"时立刻报警。

### 12.1 实施偏差记录（Step 1）

实施时对 §6 的公式做了四处收敛，均已验证等价或更优：

| 偏差 | 原计划 | 实际实施 | 原因 |
|------|--------|----------|------|
| 统一驱动量 | 两侧各传 `uTidalLambda` + `uTidalStretch`，各自算 `amp` | **CPU 只算一个 `tidalAmp`，两侧直接消费** | 原方案仍存在"两侧各写一份公式"的漂移风险；改为单点计算后 S4 由**结构**保证，而非靠纪律 |
| 幅度映射 | `amp = (Λ-1)·tidalStretch` | `amp = p/(1-p)·tidalStretch·0.30` | 原式在 $p=0.96$ 时 $amp=24$，形体被拉成 25 倍并伴随数值风险；新式加 0.30 增益把量程压到 $0\sim7.2$ |
| 鼻部渐细项 `distFactor` | 保留 | **潮汐路径移除，仅回退路径保留** | `distFactor = 1+(d_\parallel/R)\cdot amp\cdot0.1` 对幅度是**二次**增长，$amp=7.2$ 时把鼻尖推到 $\approx 57R$，彻底破坏 S4 的解析对齐 |
| `noseWidth` | $2R/(1+amp\cdot0.55)$ | $R/(1+amp\cdot0.55)$ | 流 shader 的 `w` 是**半宽**（`mask = smoothstep(1.5, 0.0, dist/w)`），原式把直径当半宽，流的起始宽度会是本体的 2 倍 |
